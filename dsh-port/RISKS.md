# Risks

Each risk has an id, a likelihood (L) and impact (I) rated low, medium or high, a mitigation, and the task that owns it. Review this list at the end of each phase.

| Id | Risk | L | I | Mitigation | Owner |
| --- | --- | --- | --- | --- | --- |
| **R-01** | **DSH is pre-release; plugin APIs change between RCs.** Every release so far is an RC, and at least one plugin path (`connection.rpc.handle`) already fails for third-party plugins | high | high | Pin the version (D-17). Keep all DSH calls in `src/host` behind small adapters; the core never imports DSH. The fake context mirrors the pinned shapes. There is an upgrade checklist (AGENT-GUIDE §7) and `docs/dsh-compat.md` | P0-01, every P2 task |
| **R-02** | **DSH Desktop may not reach the plugin's web route.** Desktop loads its UI over `file://` and "carries fetch over an IPC bridge" | medium | high | All page→host traffic goes through `HostApi` (D-12), so the transport can change in one file. P0-06 tests Desktop if a machine is available, and P5-02 must. Fallbacks, in order: `connection.rpc` if fixed; commands run through the session; document Web-only support | P0-06, P5-02 |
| **R-03** | **Child agents may not expose enough to observe them**: tool calls with arguments, thoughts, token usage and cost. Without them, the activity log, the edit log (provenance, F-12) and metrics weaken | medium | medium | P0-04 finds the hooks (`localAgent.ctx` events, `tools/result`, the child's session log, `subagent/end`). Fallbacks: read the child session after the run for usage; take edits from `git status` diffs per run | P0-04, P2-02 |
| **R-04** | **Child agents cannot ask the user** (DSH rule). The designer's direct questions and the "same agent carries on after more time" behaviour change | certain | medium | D-09: questions go into the report and the oracle asks. Time-up re-briefs until continuable children land (P4-03). Document the difference in the plugin README | P2-03, P4-03 |
| **R-05** | **In-process children share the host process.** A runaway child or a burst of parallel children can slow every DSH session | low | medium | Keep `workflow.maxParallelWorkers` (default 3), time limits, stall watchdogs and `maxDepth: 0`. `maxActiveSubagents` caps continuable children. P5-03 measures | P2-02, P5-03 |
| **R-06** | **Tool-name mismatches.** bot-lobby's prompts, role allow lists, the desk's edit detection and provenance all assume Pi's tool names | high | high | P0-03 writes `docs/tool-names.md`, and everything reads names from one module. `toolFilter` fails loud on unknown names. The guard test tries every edit-capable tool as a read-only role | P0-03, P1-10, P2-06 |
| **R-07** | **The session-log rule vs plugin state.** Task state lives in `.bot-lobby/` files; the model must still see only logged context | medium | medium | D-07 and D-20: context reaches the model only through `agent.inject()` and tool results; never append custom events. Review this in every P2 PR touching the oracle | P2-04 |
| **R-08** | **Singletons that were per-Pi-process become shared across sessions in one DSH host**: feed, brief memory, pending route, run registries | medium | high | P2-01 lists and converts them, with a two-session host test | P2-01 |
| **R-09** | **Plugin API security.** The API serves project data to a browser; it must not be callable by other sites or without login | low | high | `ctx.connection.admit(req)` on every request. Only `POST` with `content-type: application/json` (a cross-site form or simple request cannot send it without a CORS preflight, which we never grant). Body size limit. No secrets in responses. Tests for each (P2-12b) | P2-12b, P5-04 |
| **R-10** | **Settings persistence path unclear.** Volatile `Config` fields vs a storage domain vs our own file | medium | low | P0-08 decides with evidence. Fallback: a storage domain record, which is documented and simple | P0-08 |
| **R-11** | **The UI looks foreign in DSH, or breaks in dark mode or narrow layouts** | medium | medium | Tokens only, no DSH UI imports (D-11). Compare with DSH's Plugin Manager page. Light/dark and narrow checks in every UI task (TESTING §5) | P3-01, P3-14 |
| **R-12** | **Parity drift.** Features are quietly lost in the rewrite | medium | medium | FEATURE-INVENTORY → `docs/parity.md` updated per PR; the P5-07 sign-off needs evidence per row | all, P5-07 |
| **R-13** | **Model cost and flakiness in tests** | medium | low | Unit and host tests use fakes; the UI uses the mock API; live tests are opt-in and use the cheapest model the user has | TESTING §1 |
| **R-14** | **The Excalidraw public collab server changes or is unavailable** | low | low | `BOT_LOBBY_EXCALIDRAW_SERVER` override (kept); tests use the local socket.io server (`excalidraw-server.ts`) | P1-08 |
| **R-15** | **Two DSH hosts on one project** (Web and Desktop, or two profiles) could both drive a task | low | medium | Task ownership by session id stays; P4-05 adds host presence detection | P4-05 |
| **R-16** | **Session creation per task may not be possible from a plugin** | medium | medium | D-08 keeps tasks in the current session until P0-07 proves otherwise; the feature is Phase 4 | P0-07, P4-01 |
| **R-17** | **The DSH question UI cannot show bot-lobby's option previews or images** | medium | low | Put previews in `detail`; show images in our page; the designer's choices stay usable as text (D-09, P0-09) | P0-09, P4-07 |
| **R-18** | **Vendored DSH docs go stale** | certain | low | They are a snapshot (rc.2). The authority is the installed version (`cordis_inspect_query`, the installed `lib/types`). Refresh `reference/` on upgrades in the new repo | AGENT-GUIDE §7 |
