# Real-phone checklist (user-owned, non-gating)

Run on **Android Chrome** and **iPhone Safari**, in light and dark themes. Record device/OS/browser, orientation and any failure with a screenshot. Browser automation does not establish real keyboard, safe-area or audio behaviour. **All actual-device and sound checks belong to the user and are not completion gates.** Supported Chromium/WebKit automation remains a separate gate.

- [ ] Open every available non-Metrics tab; open Settings and the project switcher. Confirm slim header, no visible shortcut hints, no sideways page scrolling, and reachable first/last rows.
- [ ] Open the software keyboard: tabs collapse to the current-page handle. Reopen with the handle, choose a tab, close tabs, then dismiss the keyboard. Draft, target and attachments survive. Repeat with hardware keys connected; focus alone must not collapse tabs.
- [ ] Check safe areas with browser chrome expanded/collapsed: the whole dock stays reachable, last content rows and jump/toast controls clear it, and Thinking stays above it. Drag Thinking to every edge, resize/rotate and reopen it.
- [ ] Swipe repeatedly through both circular joins in both directions. No blank seam, snap or cross-fade. After scrolling settles, the candidate stays compact/neutral for 500ms while the old page/target remains active. More movement restarts the wait; tapping commits immediately. Check the final expanded tab centres without overlapping neighbours.
- [ ] Open full-width details from Tasks, previous Plan, Quick fix and Git (both pull requests and issues). Close/Back remain reachable; dock cannot be used underneath. Browser Back restores the list/focus. Knowledge instead stays inline: switch Docs/Chat, retain the selected document and keep using its composer.
- [ ] Open waiting questions, use Later and reopen; answer with a custom value, Next/Answer and multi-select. Cancel must ask before leaving. With the keyboard open, question actions stay reachable. Expand a mockup; Escape/close returns to the unanswered card before dismissing it.
- [ ] Rotate portrait/landscape, including short landscape: all header actions remain reachable (overflow where needed), target menu replaces target pills, and Send/Stop and fields fit. Cross 767/768 where possible without losing route, draft or attachments.
- [ ] Attach images/files on a composer-supported page (Lobby, Tasks, Plan, Quick fix or Knowledge), inspect thumbnails, remove/re-attach, navigate between tabs, send and confirm Stop. Hide the composer by visiting Git, Metrics or Settings during an upload; it must be inert, take no space and return text/attachments intact without duplicate uploads or submissions. Phone navigation stays reachable. Test a long draft, loading/upload failure and retry; nothing is silently lost.
- [ ] In Git, use Pull requests / Issues with touch and arrow keys; verify 44px targets, both detail routes, issue comments, File issue on an empty list, Plan it and unchanged PR reviews. Check disabled/loading/error states keep the switch available. Old Issues links redirect to Git; old Sessions/Excalidraw links fall back to Lobby.
- [ ] Focus the composer: only the box moves (about 360ms ease-out, within ±3% scale); the tray stays attached and stationary, with no icon wobble, gap, clipping or overflow. Reduced motion retains a visible focus indicator without the animation.
- [ ] **Sound (manual only):** unlock audio with a deliberate interaction, check prompt tones and soft navigation ticks across repeated seams, and verify the shared App sounds mute controls both. No replay queue after refusal; navigation never waits for audio. Check quiet programmatic centring/resizing. Do not treat these observations as automated evidence.
